# Важно: продакшен-конфигурация этого проекта

Этот сайт будет развёрнут на собственном VDS (не Vercel), том же сервере,
что и `site-001` (Зрелая красота) и `market-001` (market-store). Использует
переменные окружения для продакшен-настроек. При внесении изменений в
проект СОХРАНЯЙ следующую логику — не хардкодь значения, которые должны
браться из окружения.

## 1. Переменные окружения (.env.local на сервере, НЕ в git)

Файл `.env.local` на сервере должен содержать:
```
GITHUB_OAUTH_CLIENT_ID=...
GITHUB_OAUTH_CLIENT_SECRET=...
SITE_URL=https://finance.an51.su
```

Сайт рассчитан на стандартный 443 порт (HTTPS через certbot) — без порта
в конце домена, по образцу site-001.

Этот файл в `.gitignore` и не синхронизируется через git.

## 2. src/app/api/auth/route.ts

Этот файл ДОЛЖЕН брать базовый URL сайта из переменной окружения `SITE_URL`,
а НЕ вычислять его из `req.nextUrl.origin`. Причина: сайт работает за nginx
reverse proxy, и `req.nextUrl.origin` внутри Next.js видит только внутренний
адрес (`localhost:3000`), а не реальный внешний домен и протокол — из-за
этого OAuth redirect_uri ломается (в частности, может подставиться `http://`
вместо `https://`, если nginx не прокидывает `X-Forwarded-Proto`).

Правильная логика:
```typescript
const siteUrl = process.env.SITE_URL || req.nextUrl.origin;
const redirectUri = `${siteUrl}/api/callback`;
```

Fallback на `req.nextUrl.origin` можно оставить для локальной разработки, но
`SITE_URL` должен иметь приоритет.

## 3. public/admin/config.yml

Секция `backend:` должна содержать:
```yaml
backend:
  name: github
  repo: vknmurm-star/finance-001
  branch: main
  base_url: https://finance.an51.su
  auth_endpoint: api/auth
```

Если пересоздаёшь или регенерируешь этот файл — не оставляй плейсхолдеры
вида `YOUR-DOMAIN.example` или неправильный `repo` (это уже случалось на
site-001 при первой генерации). Всегда указывай реальный `repo` и
`base_url` выше. Если финальное имя репозитория на GitHub окажется другим
(например, `finance-store` вместо `finance-001`) — обнови и это поле, и
Homepage/Callback URL в OAuth-приложении на GitHub.

## 4. Процесс деплоя

Сайт задеплоен на `/var/www/finance-001` (VDS `kvm.an51.su`). Стандартный
порядок (по образцу site-001):
1. Правки вносятся локально
2. **Сначала GitHub, потом сервер**: `git add . && git commit -m "..." && git push`
3. На сервере: `cd /var/www/finance-001 && ./deploy.sh` (скрипт делает
   `git pull && npm install && npm run build && pm2 restart finance-001`,
   защищён flock'ом от параллельного запуска; лежит только на сервере,
   не в git — см. глобальный скилл `vds-nextjs-deploy` для полного
   содержимого)

**Автодеплой по cron НЕ настроен** — как и на site-001 (осознанный выбор,
не как у market-store): у CC есть прямой SSH-доступ, поэтому деплой
делается вручную по запросу пользователя, а не через периодический
polling. Если понадобится автодеплой при публикации статей через Decap
CMS — можно включить по образцу `auto-deploy-check.sh` + cron из скилла
`vds-nextjs-deploy`.

Процесс PM2 называется `finance-001`, порт Next.js — **3002** (порт на
хосте — общий ресурс, сайты его делят: site-001 слушает 3000,
market-store — 3001, поэтому finance-001 занимает следующий свободный —
3002). PM2-процесс запущен с `PORT=3002 pm2 start npm --name finance-001
-- start`; при пересоздании процесса не забыть эту переменную окружения.
nginx проксирует `finance.an51.su` → `localhost:3002` через
`/etc/nginx/sites-available/finance-001`.

## 5. Контент / CMS — те же подводные камни, что на site-001

Все статьи — `.mdx`-файлы в `content/articles/`. Строго следить за
YAML-frontmatter:

- **Поле `date` обязательно в кавычках** (`date: "2026-06-03"`).
  Незакавыченная дата парсится gray-matter/js-yaml как JS `Date`-объект
  вместо строки, что ломает `article:published_time`/`modified_time`
  (рендерятся как `[object Object]`) и атрибут `<time dateTime>`. В коде
  есть защита — функция `normalizeDate()` в `lib/articles.ts` — но кавычки
  в исходнике всё равно лучше ставить для чистоты.
- **Любое строковое поле с «двоеточие+пробел» внутри** (например
  `description: "... слово: слово ..."`) должно быть в кавычках —
  незакавыченное ломает YAML-парсинг при сборке. Проще всего — заворачивать
  в кавычки `description`/`seoDescription` всегда, не только когда там
  есть двоеточие.

Разделы (категории): Бюджет, Накопления, Долги, Привычки — на момент
запуска в каждом по 2 статьи, стараться держать баланс при добавлении
новых.

Внутренняя перелинковка обязательна: новая статья должна ссылаться на
минимум одну существующую статью по теме.

**Тон и ограничения контента** (жёстче, чем на site-001, из-за специфики
темы):
- Простой язык, без снобизма, без предположения, что у читателя уже
  высокий доход.
- **Никаких конкретных инвестиционных советов**, рекомендаций по продуктам
  конкретных банков/брокеров, обещаний доходности — только общие принципы
  и практики.
- Без осуждения за долги/отсутствие накоплений/«поздний старт».
- Рассылка по email сознательно НЕ реализуется на этом сайте (как и на
  site-001) — если всплывёт похожий блок подписки, по умолчанию удалять,
  а не подключать.

## Дизайн-система

- Палитра — тёмно-синий/графит (`--color-navy`, `--color-ink`) + один яркий
  акцент на секцию: бирюзовый (teal, Бюджет), зелёный (green, Накопления),
  янтарный (amber, Долги), индиго (indigo, Привычки).
- Шрифт — чистый sans-serif везде (системный стек), без serif-заголовков —
  осознанное отличие от редакционного/serif-стиля site-001, чтобы сайты не
  путались визуально.
- Логотип — простой геометричный SVG-знак (растущая линия/чек в бирюзовом
  на тёмно-синем квадрате), а не фото/эмблема как на site-001 (там лого
  предоставил пользователь вручную). Растрирован в `src/app/icon.png` /
  `apple-icon.png` через `sharp`.

## Изображения к статьям

Через `content-factory-001` (fal.ai). Промпт-чеклист реалистичности —
как на site-001: видимые поры, асимметрия лица, выбившиеся пряди волос,
неидеальные зубы, лёгкое зерно плёнки, **без зеркал/отражений в кадре**.

Сюжеты — человек дома за бюджетным планированием (блокнот, ноутбук,
конверты, звонок в банк), **без клише** в духе стоковых фото
«крупный план калькулятора и денег» или рукопожатий у стола переговоров.

## SEO / GEO — чеклист (как на site-001)

- Уникальные meta-теги, canonical, OG/Twitter — на всех типах страниц
- JSON-LD: Article (+ HowTo там, где в статье есть чёткий пошаговый
  алгоритм — например, «Как разобраться с несколькими кредитами»),
  BreadcrumbList, CollectionPage/ItemList на категориях, Organization +
  WebSite (с SearchAction на `/search?q=`) в layout
- Alt-текст на всех изображениях — содержательный, не название файла
- `sitemap.xml` и `robots.txt` с реальным `SITE_URL`; GEO-краулеры
  разрешены (GPTBot, ChatGPT-User, OAI-SearchBot, PerplexityBot,
  ClaudeBot, Claude-Web, Google-Extended, Applebot-Extended) — закрыты
  только `/admin` и `/api`
- Верификация Google Search Console / Яндекс.Вебмастер через
  `metadata.verification` в `layout.tsx` — коды ещё НЕ добавлены на
  момент создания проекта, нужно вписать после верификации домена
- Яндекс.Метрика — тоже ещё не подключена, добавить по образцу site-001
  (`next/script`, стратегия `afterInteractive`) после получения счётчика

## SSH-доступ к серверу

Тот же сервер и ключ, что для site-001 и market-001:
```
ssh root@kvm.an51.su
```
Пользователь — `root`, беспарольно по ключу.

**Сервер общий с site-001 и market-store.** При правках nginx или
системных настроек:
- перед любым `systemctl reload nginx` — сначала `nginx -t`;
- после reload — проверить, что ВСЕ сайты отвечают 200:
  ```
  curl -s -o /dev/null -w "%{http_code}\n" https://beauty.an51.su/
  curl -s -o /dev/null -w "%{http_code}\n" https://market.an51.su/
  curl -s -o /dev/null -w "%{http_code}\n" https://finance.an51.su/
  ```

**Не перебирай имена пользователей залпом** — сразу под `root`, иначе
fail2ban на ~10 минут блокирует IP на порту 22.
